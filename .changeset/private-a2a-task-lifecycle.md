Bind A2A task reads, cancellation, and execution reservations to trusted actor/account scope. Reject colliding task IDs before metering, consume execution reservations once, and preserve cancellation when a provider finishes or rejects afterward. Continue pending-payment tasks only with unchanged input and the existing payment verifier's successful result.

Public API migration: pass an authenticated `AgentActionScope` to task creation/read/cancellation and a trusted canonical agent/definition binding when creating reservations. Pass the same scope through the JSON-RPC handler options; omitted scope fails closed. Scope comes from authenticated middleware and resolved account context, never request metadata. Existing unscoped global access is intentionally removed.

Attributed version-one history remains accessible in the existing scoped history endpoint, with caller receipt metadata removed from exposed params/results. Version-one rows cannot authorize task replay or unpaid execution restoration. Version-two task results rebuild receipt status from server-owned durable fields; unrelated historical actions remain historical data.

This does not provide cross-task payment-proof consumption: `packages/paywall/src/x402/index.ts` calls facilitator `/verify` and exposes no settlement or durable nonce claim. That owning payment boundary needs verified settlement/nonce binding and cross-task replay tests before paid readiness can be claimed. The server now reserves the stable task ID atomically in attributed version-two `agentActions` rows before quota/provider execution and awaits terminal persistence. Owned reads replay durable terminal outcomes; failed receipt writes preserve the known outcome and support persistence-only recovery through the same owned task read. Unresolved pending/running records after restart return unknown and never automatically reexecute. Only validated, unchanged unpaid reservations may continue through the existing proof verifier and an atomic execution claim. This is not an exactly-once guarantee across the provider and database, or a general restart-readiness claim. Bounded admission/retention remains separately tracked.

The existing `apps/server/src/middleware/x402.ts` verification contract receives payload, resource, and endpoint, while `apps/server/src/routes/a2a.ts` advertises the frozen agent definition's `pricing.usdc`. It does not pass that agent identity or frozen quote into verification. Extend the owning paywall proof/settlement contract to bind the authenticated task's agent, exact resource, and expected quote; validate insufficient amounts, wrong-agent/resource proofs, cross-task replay, and actual settlement before claiming paid execution readiness. The task's one-use execution claim preserves the existing verifier contract and does not supply those missing payment guarantees.

Memory and fair admission remain unbounded in the owning task store. The server's maintained `body-limits.ts` caps HTTP JSON at 1MiB, but `packages/contracts/src/a2a/index.ts` has no retained message/artifact/history byte limits, direct handler calls bypass that HTTP gate, and provider output is not bounded before retention. `apps/server/src/app.ts` rate limits A2A discovery but not the dispatcher/stream; it supplies no trusted actor/account active cap. After durable receipts, extend the existing A2A validation/configuration, dispatcher rate-limit middleware, and same private entry with total/per-scope admission and retained-byte ceilings. Protect unpersisted terminal outcomes from eviction; verify authenticated DB replay parity, oversized inputs/outputs, one-principal saturation, and protected receipt-write-failure capacity. Pass model-derived output limits through the existing chat contract; do not truncate output and claim successful delivery.

Agent authoring remains a separate security prerequisite: `packages/db/src/schema/agents.ts` defines `registeredAgents` without actor/account ownership, while `apps/server/src/routes/a2a.ts` exposes global PUT for built-in/custom definitions and DELETE for custom definitions. Registry mutation currently changes memory first and persists best-effort. The durable target is authenticated authoring authority in the owning schema/registry CRUD plus canonical memory/storage consistency, with cross-account and built-in mutation denial, no mutation on denial, and storage-failure regression tests. Frozen task execution bindings prevent continuation drift; they do not repair registry authoring authority.

The declared server prerequisite build passed 20/20 tasks; full AI and server typechecks passed. Canonical API artifacts must be generated after stack convergence; no live rollout or production readiness is asserted by these receipts.
