# GAP-381 D-C — VS Code Marketplace publisher listing

**Decision (design §8 D-C):** Marketplace publisher account + listing is an
**owner operation**. Phase C ships **local path** install only
(`chat.pluginLocations`). Public connect guide states this honestly.

**Agent slice already shipped:**

- Generator: `packages/harnesses/src/content/generators/vscode.ts`
- Local install notes: `packages/harnesses/docs/vscode-agent-plugin.md`
- Public guide: `docs/guides/connect-vscode.md`

## Why this stays owner-gated

- Requires Microsoft/GitHub publisher identity, publisher agreement, and
  ongoing listing maintenance (Preview surface; high release cadence).
- Publishing a malicious or stale plugin would bind the org brand.
- Org-allowlist MCP registry is a **customer** admin action (GitHub Copilot
  policies), not something the monorepo automates.

## Publish sequence (high level)

Exact marketplace UI names change; re-verify against Microsoft docs the day you
publish.

1. **Package the bundle** generated by `VSCodeGenerator` (project
   `.revealui/vscode-plugin/` plus leak-proof `.mcp.json` template that never
   embeds a token).
2. **Validate** plugin.json schema against current VS Code agent-plugin docs
   (hooks still command-based only; MCP still path/input refs).
3. **Publish** under the RevealUI Studio publisher account.
4. **Document** install-from-marketplace path in
   `docs/guides/connect-vscode.md` (one short section) only after the listing
   is live and smoke-tested by the owner.
5. **Record** listing URL + version in GAP-381 residual note; mark D-C done.

## Explicit non-goals

- Do not commit device tokens or live instance URLs into the plugin package.
- Do not claim org-wide enforcement without GitHub Copilot registry policy.
- Do not block customers: local `chat.pluginLocations` remains the supported
  path until D-C is complete.
